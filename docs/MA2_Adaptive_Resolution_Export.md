# MA2 自适应分辨率导出与最小 Grid 修复流程

最后更新：2026-07-30 +08:00

状态：已实现并通过转换器回归测试与目标行为模拟验证。

## 目标

MajdataEdit 将 Simai 转换为 MA2 时，默认从 `RESOLUTION = 384` 开始计算。
如果微小正时间被量化为零，或量化后的 Slide 拓扑会被目标游戏错误串接，
转换器自动尝试更高的谱面级固定分辨率，最大不超过 `192000`。

如果所有合法分辨率仍无法生成安全结果，则在最大合法分辨率下执行最小
Grid 修复。任何修复都只作用于本次导出的中间模型，默认不改写原始
`maidata.txt`，并且必须生成可追溯的调整报告。

本设计中的“自适应分辨率”表示每张 MA2 可以选择不同的全局
`RESOLUTION`，不表示在同一张谱面中途切换分辨率。

## 实现位置

- `Ma2Export/SimaiChartConverter.cs`：解析一次、候选分辨率生成、分段 BPM
  Grid 换算、Slide 分段生成、拍号和统计输出；
- `Ma2Export/Ma2AdaptiveResolutionEngine.cs`：临时 MA2 记录解析、游戏
  `calcSlide` 顺序模拟、`float msec` 检查、最小 Grid 修复和最终验证；
- `Ma2Export/Ma2ExportModels.cs`：转换选项、结果和逐项调整报告；
- `ForceYellowValidation/Program.cs`：自适应分辨率与边界回归用例；
- `MainWindow.xaml.cs`、`MusicXmlExport/*`：导出提示和报告展示。

原有 `ConvertChartToMa2Content(...)` API 保持兼容。需要读取报告时使用
`ConvertChartToMa2(...)`；直接导出和 Music.xml 导出都会明确显示非 384
分辨率及自动调整摘要。

## 固定约束

```text
默认分辨率：384
最低分辨率：384
最高分辨率：192000
基础兼容步长：384
整数输出范围：0..Int32.MaxValue
中间计算类型：Int64 或更宽
```

转换器只输出一组全局定义：

```text
RESOLUTION    最终 R
CLK_DEF       最终 R
```

## 总体流程

```text
解析 Simai
  ↓
建立来源、BPM、EACH、Head Group 和 Slide 分段模型
  ↓
生成合法候选分辨率
  ↓
从最低候选 R 开始重新量化
  ↓
模拟游戏整数 Grid、float 毫秒和 Slide 串接
  ↓
通过 ─────────────────→ 输出 MA2
  ↓ 未通过且仍有候选 R
尝试下一个合法 R，最大不超过 192000
  ↓ 全部未通过
在最大合法 R 下执行最小 Grid 修复
  ↓
重新模拟全部游戏行为
  ↓
通过则输出并报告修复；仍失败则阻止导出
```

## 阶段一：解析与中间建模

1. 使用 MajSimaiX 完整解析 Simai。
2. 暂不拼接 MA2 文本，先建立与输出格式解耦的中间模型。
3. 每条物件至少保存以下来源和逻辑信息：

   - Simai 行号、列号和原始文本；
   - 原始开始、结束、等待和持续秒数；
   - 时间是否为显式零；
   - 所属 BPM 区间；
   - Slide 分支 ID 和段索引；
   - 根段、CN 段或 Wifi 段；
   - 起点和终点键位；
   - Head Group ID；
   - EACH Group ID；
   - Mine、Force Yellow、Soflan 等导出属性。

4. 在量化前完成连接 Slide 拆段。
5. N 段共享总时间时，建立 N 个独立段，同时保留共享总时长约束。
6. 建立完整 BPM 时间线，供任意时间点进行秒数和 Grid 换算。

Head Group 用于标识必须保持同刻的星头、根 Slide 和同头分支。EACH Group
用于防止自动调整拆散原本同时出现的物件。

## 阶段二：生成候选分辨率

先计算合法步长：

```text
baseStep = LCM(384, 4, 所有有效拍号分母)
```

候选值为 `baseStep` 的正整数倍，并且必须满足：

```text
384 <= R <= 192000
R % 4 == 0
R % 所有有效拍号分母 == 0
```

普通 4/4 谱面使用以下候选序列：

```text
384, 768, 1152, 1536, ... , 192000
```

如果不存在合法候选值，则直接阻止导出并报告拍号与分辨率约束冲突。

每次尝试都必须从原始中间模型重新量化，禁止缩放前一个候选的量化结果，
避免累积舍入误差。

## 阶段三：分段 BPM Grid 换算

对于时间 `t`，先找到其所在 BPM 区间 `i`，再计算：

```text
Grid(t) =
    BaseGrid[i]
    + Round(
        (t - BaseTime[i]) * R * BPM[i] / 240,
        MidpointRounding.ToEven
      )
```

跨越 BPM 边界的长度统一通过两个绝对时间点计算：

```text
LengthGrid = Grid(endTime) - Grid(startTime)
```

禁止只使用物件开始位置的 BPM 计算跨 BPM 的完整长度。

使用同一个 Grid 映射器重新计算：

- Tap、Touch、Star 和 Hold；
- Slide 起点、等待和持续长度；
- BPM、MET、SFL、Click 和其他 Composition 事件；
- 所有 Hold/Slide 的派生结束位置；
- 谱面终止位置。

## 阶段四：候选结果验证

对每个候选分辨率生成临时 MA2 记录，但在验证通过前不写文件。

验证器必须模拟目标游戏的以下行为：

1. 星头与普通根 Slide 的匹配；
2. Slide 结束时间和目标键位匹配；
3. CN 父子关系建立；
4. 普通根 Slide、自返 Slide 和跨分支 Slide 的候选关系；
5. Grid 到游戏 `float msec` 的时间换算；
6. 谱面结束时间的派生计算。

候选结果必须同时满足：

```text
普通根 Slide 被捕获数 = 0
根 Slide 自连接数 = 0
跨分支连接数 = 0
孤立 CN 数 = 0
星头与根 Slide 不一致数 = 0
EACH 关系意外改变数 = 0
正时间量化为零数 = 0
正运行时持续时间折叠数 = 0
整数溢出数 = 0
非法拍号边界数 = 0
```

“正运行时持续时间折叠”表示开始和结束 Grid 不同，但使用游戏相同的
单精度浮点换算后，开始和结束 `msec` 相等或不再递增。

所有乘法、加法和缩放使用 `Int64` 或更宽类型。写入 MA2 前，再验证每个
最终值能够安全转换为非负 `Int32`。

第一个完全通过验证的候选 `R` 即为最终分辨率。

## 阶段五：最大分辨率下的最小 Grid 修复

如果所有候选均失败，则使用不超过 `192000` 的最大合法候选进入修复模式。

对于原始值大于零，但整数 Grid 或游戏毫秒发生折叠的时间段，寻找满足
以下条件的最小 `k`：

```text
k >= 1
EndGrid >= StartGrid + k
CalcGameMsec(EndGrid) > CalcGameMsec(StartGrid)
```

修复规则：

- 正等待至少分配满足条件的 `k` grid；
- 正 Slide 段至少分配满足条件的 `k` grid；
- N 段共享正持续时间时，总长度至少为各段最小 Grid 之和；
- 显式零时间不自动扩展，只保留或报告；
- 调整一段后，重新计算同分支所有后续段；
- 每项调整必须保存调整前后 Grid、毫秒和来源行号；
- 修复只作用于导出模型，不修改原始 Simai 文件。

最小 Grid 修复完成后必须重新执行完整验证，不能直接输出。

## 阶段六：处理精确接触

如果独立根 Slide 仍与上一条 Slide 精确接触，则按以下顺序尝试修复：

1. 优先缩短前一条冲突 Slide 的最后一段；
2. 使用能够解除冲突的最小 Grid 调整量；
3. 缩短后必须保持该段有效，并且不能破坏其 CN 连接；
4. 无法缩短时，移动后一条完整 Head Group；
5. Head Group 包括星头、根 Slide 和所有同头分支；
6. 如果该物件属于 EACH，则必须移动完整 EACH Group；
7. 如果移动会制造其他冲突，则撤销该方案并阻止导出。

自动调整必须具有有限的尝试次数和最大允许偏移，防止修复过程循环或产生
不可控的时间漂移。任何精确接触修复都不能静默执行。

## 阶段七：最终验证与输出

修复后重新执行阶段四的全部检查，并额外确认：

- 最后一个 Hold/Slide 的派生结束时间有效；
- 谱面终止位置晚于所有物件；
- 所有 Grid 和长度处于 `Int32` 范围；
- 游戏毫秒时间保持非递减；
- 没有未记录或无法解释的自动调整。

验证通过后输出最终 MA2：

1. 写入唯一的 `RESOLUTION` 和 `CLK_DEF`；
2. 所有 Note 和 Composition 记录使用同一个最终 `R`；
3. 从最终记录重新计算 `T_REC_*`、`T_NUM_*`、`T_JUDGE_*` 和分数统计；
4. 保持 Mine、Force Yellow、Soflan 等扩展尾字段的既有输出约定；
5. 生成导出和调整报告。

报告至少包含：

```text
初始分辨率：384
最终分辨率：R
尝试候选数：N
自动调整物件数：N
最大 Grid 调整量：N
最大毫秒调整量：N ms
调整物件及 Simai 行号：...
剩余警告：无
```

只要最终验证有一项失败，就不得写出 MA2 文件。错误报告必须显示相关
Simai 行号、原始文本、冲突 Grid、冲突物件和失败原因。

## 兼容性与默认行为

- 无问题谱面继续优先使用 `RESOLUTION = 384`；
- 自适应过程始终选择第一个完全通过的最小合法分辨率；
- 默认不改写原始 `maidata.txt`；
- 自动 Grid 修复必须在界面和报告中明确展示；
- 非 384 MA2 只保证目标游戏配置，其他 MA2 工具可能存在固定分辨率假设；
- 固定 384 导出模式应继续保留，供需要最大外部兼容性的用户选择。

## 验收标准

实现完成后至少覆盖以下场景：

- 无冲突谱面保持 384 且输出行为不变；
- 微小正等待或持续时间触发分辨率提升；
- 多段共享时长的 Slide 按段验证；
- 变 BPM Hold/Slide 使用分段 Grid 映射；
- 普通根 Slide 不会被误识别为 CN；
- 自返 Slide 不会连接到自身；
- 精确接触按照既定优先级调整；
- Head Group 和 EACH Group 不会被拆散；
- 高分辨率下相邻 Grid 的 `float msec` 折叠可以被发现；
- 拍号不整除、`Int32` 溢出和非法结束时间会阻止导出；
- 最终统计与实际输出记录一致；
- 导出失败时不会留下部分写入的 MA2 文件。

Simai 和 MA2 文件并模拟游戏计算，没有读取 Package 目录中的游戏日志。

```text
旧 MA2：R=384，710 分支，1500 段

自连接：6

声明分支数：479
```

联动测试项目的 `artifacts/adaptive-ma2/115001_00.adaptive.ma2`。
